# Subprocessor Register

## Current Subprocessors

The default native Compose deployment provisions no hosted application subprocessor on the user's behalf: PostgreSQL/pgvector and attachments run in the operator's infrastructure. Container registries and npm supply software during build; this is not evidence that CRM records are sent to those registries. Next telemetry is disabled in the supplied Dockerfile.

Optional model, Microsoft mail/calendar and monitoring integrations require the operator's own configuration. An open-source dependency is not automatically a data processor; an enabled external service may be. This repository cannot enumerate the actual suppliers used by every independent installation.

The operator must keep a private inventory with supplier, purpose, transmitted fields, region, account owner, retention, access and contract reference. Record explicit disabled status for unused integrations; never include credentials in the public register.

## Change Management

Before enabling or changing a provider, review its endpoint, data handling, region and terms, test with synthetic data, and obtain the organization's required approval. Update the private inventory and customer notices as applicable. Removing application configuration does not delete copies already held by a provider; request and verify deletion separately.
