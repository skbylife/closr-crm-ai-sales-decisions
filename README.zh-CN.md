# Closr：面向复杂 B2B 销售的自部署 AI CRM

**理解客户，看清局面，确定下一步。**

[官方网站](https://www.closr.ing) · [English](README.md) · [自部署指南](SELF_HOSTING.md) · [许可](LICENSE)

Closr 是面向复杂 B2B 销售的自部署 AI CRM，将销售情报与商机洞察融入团队日常工作台。销售判断（Sales Judgment）连接客户沟通和客户历史，通过 BABEL 分析关键人物与决策关系，用谋局（Strategic Plays）形成可执行的销售行动手册，并支持 RFP 投标／不投标评估，让团队能够对照证据复核判断、确定下一步。

围绕一笔复杂交易，团队可以一起审视：**发生了什么变化、还缺什么证据、谁影响决策、下一步应该验证什么**，再将判断组织成有步骤、负责人和后续行动的谋局计划。

本仓库按 **source-available（源码可用）许可**公开完整应用、BABEL 引擎、Prompt、策略实现和可读通用知识，取代此前功能有限的 Community 预览。

## 为什么做 Closr

复杂 B2B 销售的局面很难用一个阶段和预计成交日期概括。客户可能仍在回复，但预算负责人始终没有参与；索要案例可能代表兴趣，也可能意味着缺少关键证明；采购新角色的加入可能改变整个决策路径。

Closr 将这些信号放到同一个客户工作台，帮助团队对照原始材料、识别不确定性，并形成下一步行动。AI 输出是供人复核的假设，不代表能够知道客户的真实心理，也不保证成交。

## 适合谁

- **销售与客户经理**：推进多角色参与的复杂销售、续约与扩展。
- **销售负责人和解决方案团队**：共同审视风险、关键人物覆盖、所需证明及投标决策。
- **创业者、销售运营与技术团队**：检查、修改并自行运行 CRM 和销售判断流程。

## 核心工作流

### 解读：用 BABEL 理解客户沟通

对客户邮件、会议记录、通话转录、聊天文本及有权使用的外部信息进行分析，梳理意图信号、紧迫度、风险、机会和可能的回应方式。结合原文与客户背景复核解读，确定下一步该问什么、验证什么。

### 人物画像：积累关键人物与客户记忆

将联系人、角色、关系、互动及客户历史连接起来。BABEL 根据沟通记录提出决策风格、沟通偏好、风险和接触方式建议，并提供证据与置信度字段。人物画像和文化背景是需要持续验证的工作假设，不是心理诊断，也不是对个人的确定事实判断。

### 判断层：让销售判断可以被检验

梳理客户与商机的健康度、推进动量、支持与冲突证据、不确定性、证据缺口和下一步动作。来源追溯与人工反馈帮助团队回顾判断为什么改变，而不只依赖评分或生成摘要。

### 谋局：把判断变成一步步推进路径

当团队不知道如何推进时，将对关键人物的理解转化为具体路径：先接触谁、验证什么、准备什么证明，以及局面变化后如何调整。

谋局把客户痛点、方案匹配、所需证明、决策标准、人物关系和时机组织为可执行计划，记录假设、步骤、负责人、预期信号和备选动作，随着新证据持续复核与更新。

### RFP：连接招投标材料与推进策略

围绕客户和商机管理招标要求、文档、竞争对手及里程碑，审阅 AI 辅助的投标／不投标判断与建议，并连接谋局和后续工作。系统中的估计仅作为决策输入，不是经过验证的中标预测。

### 日常 CRM：让执行与判断保持连接

管理客户、联系人、商机、销售管线、任务和附件，记录活动、结果与人工修正，为下一次客户复盘保留上下文。

```text
客户沟通 + CRM 记录 + RFP 信息
              ↓
  BABEL 解读 + 人物画像与客户记忆
              ↓
    证据、冲突信息与待验证事项
              ↓
       可复核的客户／商机判断
              ↓
      谋局 → 任务执行 → 结果反馈
```

## BABEL 与公开知识内容

仓库包含 [BABEL 实现与 Prompt](src/lib/babel-engine/)、[谋局引擎](src/lib/strategic-play-engine.ts)和[判断引擎](src/lib/engine/)。运行这份源码不需要接入另行托管的私有 Closr Engine。

[可读通用知识库](data/knowledge/README.md)包含 **58 条内容**：52 条方法论笔记与 6 个文化画像。其中 8 条通用案例还会导入策略案例表。条目带有来源、内容哈希与授权说明；这些是仓库自有摘要和 Prompt 材料，引用框架名称并不代表取得对应书籍或专有数据集的再发布权利。

使用 PostgreSQL **pgvector** 支持向量检索。默认导入不需要模型凭据，可使用关键词检索；部署者可明确选择自己的供应商，重建兼容的 1536 维 embedding。不分发生产向量，也不声称这是完整生产知识库。GitHub 中缺失的历史外部策略数据集已在知识说明中注明。

## 自部署

默认架构为 **PostgreSQL + pgvector**、应用自有账号／会话／MFA，以及保存私有附件的 Docker 卷，**不需要 Supabase 账号或服务**。源码保留可选的旧 Supabase 后端。

安装 Git、Docker（含 Compose v2）和 Node.js 22。如果网络使用企业 TLS 代理，先按自部署指南中的替代构建命令操作。直连网络运行：

```sh
git clone https://github.com/skbylife/closr-crm-ai-sales-decisions.git
cd closr-crm-ai-sales-decisions
node scripts/native-init.mjs
docker compose --env-file .env.self-hosted -f docker-compose.self-hosted.yml up --build -d
```

打开 `http://localhost:3000/setup` 创建工作空间与首位所有者。配置、备份、恢复、数据库迁移与部署边界见 **[自部署指南](SELF_HOSTING.md)**。

AI 功能需要部署者自行配置模型供应商。默认 Compose 关闭 AI，知识导入不会调用模型；仓库不提供 API key 或托管服务访问权。发送客户信息前，应评估所选供应商的数据处理方式。
